# H-MAP Deployment Guide

This deploys H-MAP on the same Parañaque LGU VPS that hosts the HRMO Portal
(`103.5.62.166`, SSH `user1@dbsvr`), under two environments that mirror
the HRMO pattern:

| Environment | URL | Directory | DB | Data |
|---|---|---|---|---|
| **Production** | `https://hrmo.paranaque.gov.ph/hmap/` | `/var/www/html/hmap` | `hmap_db` | Real PIDSR |
| **Staging / Demo** | `http://hrmo.paranaque.gov.ph:8080/hmap/` | `/var/www/html/hmap_staging` | `hmap_db_demo` | Anonymized |

The staging URL is what the defense panel will see. Both environments share
the same Nginx server blocks that already serve HRMO — we just add a
`location /hmap/` to each one.

```

  Browser ── https://hrmo.paranaque.gov.ph/hmap/ ───────┐    │  PHP-FPM         │
                                                          ├──► │  Laravel (hmap)  │
                                                          │    └─────────────────┘
                                                          │
                                                          │    ┌─────────────────┐
                                                          └──► │  FastAPI (ml)    │
                                                               │  127.0.0.1:5001  │
                                                               └─────────────────┘
                                                                       │
                                                                       ▼
                                                               ┌─────────────────┐
                                                               │  MySQL 8.x      │
                                                               │  hmap_db        │
                                                               │  hmap_db_demo   │
                                                               └─────────────────┘
```

ML service ports:
- Production FastAPI: `127.0.0.1:5001`
- Staging FastAPI:    `127.0.0.1:5002`
(Avoiding 5000 which collides with macOS AirPlay if anyone runs this on a Mac.)

## One-time server setup

> Everything below is run on `user1@dbsvr` over SSH.

### 1. Install Python 3.12

> **Likely blocked on focal — same root cause as PHP 8.x.** If `apt install python3.12`
> fails with "Unable to locate package," install via deadsnakes PPA:
> `sudo add-apt-repository ppa:deadsnakes/ppa && sudo apt update && sudo apt install python3.12 python3.12-venv python3.12-dev`
> If deadsnakes also dropped focal, fall back to Python 3.8 (focal's default) +
> minor edits to `ml/requirements.txt` to use library versions that support 3.8.

```bash
# Check first; skip the install block if `python3.12 --version` works.
python3.12 --version || sudo apt-get update && sudo apt-get install -y \
    python3.12 python3.12-venv python3.12-dev build-essential
```

### 2. Create the two MySQL databases

```bash
sudo mysql
```
Then in MySQL (use the same password the `hris` user already has):

```sql
CREATE DATABASE hmap_db        CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE DATABASE hmap_db_demo   CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
GRANT ALL PRIVILEGES ON hmap_db.*      TO 'hris'@'localhost';
GRANT ALL PRIVILEGES ON hmap_db_demo.* TO 'hris'@'localhost';
FLUSH PRIVILEGES;
EXIT;
```

### 3. Clone both directories

```bash
sudo mkdir -p /var/www/html/hmap /var/www/html/hmap_staging
sudo chown -R user1:user1 /var/www/html/hmap /var/www/html/hmap_staging

# Production
git clone <REPO_URL> /var/www/html/hmap
cd /var/www/html/hmap && git checkout main

# Staging
git clone <REPO_URL> /var/www/html/hmap_staging
cd /var/www/html/hmap_staging && git checkout develop
```

### 4. Install Composer + Node dependencies (both dirs)

```bash
# Production
cd /var/www/html/hmap/laravel
composer install --no-dev --optimize-autoloader
npm ci && npm run build
php artisan key:generate

# Staging
cd /var/www/html/hmap_staging/laravel
composer install --no-dev --optimize-autoloader
npm ci && npm run build
php artisan key:generate
```

### 5. Configure Laravel `.env` (both)

**Production** (`/var/www/html/hmap/laravel/.env`):
```ini
APP_NAME=H-MAP
APP_ENV=production
APP_KEY=<generated by artisan key:generate above>
APP_DEBUG=false
APP_URL=https://hrmo.paranaque.gov.ph/hmap
ASSET_URL=https://hrmo.paranaque.gov.ph/hmap

DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=hmap_db
DB_USERNAME=hris
DB_PASSWORD=<same password the HRMO app uses>

HMAP_HRMO_MODE=php
HMAP_HRMO_SESSION_PATH=/var/lib/php/sessions
HMAP_HRMO_SESSION_COOKIE=PHPSESSID

HMAP_ML_URL=http://127.0.0.1:5001
```

**Staging / Demo** (`/var/www/html/hmap_staging/laravel/.env`):
```ini
APP_NAME=H-MAP Demo
APP_ENV=staging
APP_KEY=<generated by artisan key:generate above>
APP_DEBUG=false
APP_URL=http://hrmo.paranaque.gov.ph:8080/hmap
ASSET_URL=http://hrmo.paranaque.gov.ph:8080/hmap

DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=hmap_db_demo
DB_USERNAME=hris
DB_PASSWORD=<same>

# stub auth so the panel doesn't need an HRMO account
HMAP_HRMO_MODE=stub
HMAP_HRMO_STUB_USER_ID=999
HMAP_HRMO_STUB_USER_NAME=Defense Panel
HMAP_HRMO_STUB_USER_ROLE=Administrator

HMAP_ML_URL=http://127.0.0.1:5002
```

Permission fix-up:
```bash
sudo chown -R www-data:www-data /var/www/html/hmap/laravel/storage \
                                  /var/www/html/hmap/laravel/bootstrap/cache \
                                  /var/www/html/hmap_staging/laravel/storage \
                                  /var/www/html/hmap_staging/laravel/bootstrap/cache
sudo chmod -R 775 /var/www/html/hmap/laravel/storage \
                   /var/www/html/hmap_staging/laravel/storage
```

### 6. Set up Python venv + ML service (both)

```bash
# Production
cd /var/www/html/hmap/ml
python3.12 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env   # then edit with prod DB creds + PORT=5001

# Staging
cd /var/www/html/hmap_staging/ml
python3.12 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env   # then edit with demo DB creds + PORT=5002
```

`ml/.env` for production:
```ini
DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=hris
DB_PASSWORD=<same>
DB_NAME=hmap_db
ML_PORT=5001
```

`ml/.env` for staging — same but `DB_NAME=hmap_db_demo` and `ML_PORT=5002`.

### 7. systemd units for FastAPI

`/etc/systemd/system/hmap-ml.service` (production):
```ini
[Unit]
Description=H-MAP ML service (FastAPI)
After=network.target mysql.service

[Service]
Type=simple
User=www-data
Group=www-data
WorkingDirectory=/var/www/html/hmap/ml
EnvironmentFile=/var/www/html/hmap/ml/.env
ExecStart=/var/www/html/hmap/ml/.venv/bin/uvicorn main:app --host 127.0.0.1 --port 5001
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

`/etc/systemd/system/hmap-ml-staging.service`:
```ini
[Unit]
Description=H-MAP ML service (FastAPI, demo)
After=network.target mysql.service

[Service]
Type=simple
User=www-data
Group=www-data
WorkingDirectory=/var/www/html/hmap_staging/ml
EnvironmentFile=/var/www/html/hmap_staging/ml/.env
ExecStart=/var/www/html/hmap_staging/ml/.venv/bin/uvicorn main:app --host 127.0.0.1 --port 5002
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

Enable both:
```bash
sudo systemctl daemon-reload
sudo systemctl enable --now hmap-ml hmap-ml-staging
sudo systemctl status hmap-ml hmap-ml-staging   # both should be "active (running)"
```

### 8. Nginx — add `location /hmap/` to both server blocks

**Edit `/etc/nginx/sites-enabled/hrmo.paranaque.gov.ph`** (port 443). Inside the
existing `server { ... }` block for the HRMO site, add this block BEFORE the
final `location / { ... }` that serves HRMO:

```nginx
# ─── H-MAP (Laravel + FastAPI) under /hmap/ ──────────────────────────────
location ^~ /hmap/build/ {
    alias /var/www/html/hmap/laravel/public/build/;
    access_log off;
    expires 1y;
    add_header Cache-Control "public, immutable";
}

location ^~ /hmap/api/ {
    # Strip /hmap so Laravel sees /api/...
    rewrite ^/hmap(/api/.*)$ $1 break;
    try_files $uri $uri/ /index.php?$query_string;
    root /var/www/html/hmap/laravel/public;

    location ~ \.php$ {
        fastcgi_pass unix:/run/php/php7.4-fpm.sock;
        fastcgi_index index.php;
        fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
        include fastcgi_params;
    }
}

location ^~ /hmap/ {
    alias /var/www/html/hmap/laravel/public/;
    try_files $uri $uri/ @hmap;

    location ~ \.php$ {
        fastcgi_pass unix:/run/php/php7.4-fpm.sock;
        fastcgi_split_path_info ^(.+\.php)(/.+)$;
        fastcgi_param SCRIPT_FILENAME $request_filename;
        include fastcgi_params;
    }
}

location @hmap {
    rewrite ^/hmap/(.*)$ /hmap/index.php?/$1 last;
}
```

**Edit `/etc/nginx/sites-enabled/hrmo-staging`** (port 8080). Same block,
but every `/var/www/html/hmap` → `/var/www/html/hmap_staging`.

**Reload Nginx (use restart, not reload — see HRMO memory):**
```bash
sudo nginx -t && sudo systemctl restart nginx
```

> **PHP-FPM socket path note:** Both HRMO and H-MAP run on PHP 7.4
> (`/run/php/php7.4-fpm.sock`). H-MAP was downgraded to Laravel 8.83 to
> share the existing PHP runtime on this server because PHP 8.x installation
> is blocked on Ubuntu 20.04 (focal) until the OS is upgraded to 22.04
> (jammy) — see HRMO memory `project_php_upgrade_blocked_2026_05_20.md`.

### 9. Load the schema + anonymized demo data

```bash
# Production: real schema, real data will come from a separate xlsx-driven ETL
cd /var/www/html/hmap
.venv/bin/mysql -u hris -p hmap_db < ml/schema.sql

# Staging: load the anonymized dump from the dev's machine
# (run this on the DEV machine, not the server)
scp ml/_hmap_db_demo.sql user1@dbsvr:/tmp/
ssh user1@dbsvr 'mysql -u hris -p hmap_db_demo < /tmp/_hmap_db_demo.sql'

# Then re-run cluster detection against the demo DB so the Clusters tab
# has data:
ssh user1@dbsvr 'cd /var/www/html/hmap_staging && \
    DB_NAME=hmap_db_demo ml/.venv/bin/python ml/detect_clusters.py'
```

For production's real-data load, run the ETL **on the dev machine pointing
at the server's MySQL** (UFW + grants required — see HRMO project's
`project_prod_db_ufw_allowlist.md` for the pattern):

```bash
# Dev machine, after UFW/grant set up:
cd c:/xampp/htdocs/hmap/ml
DB_HOST=103.5.62.166 DB_NAME=hmap_db python etl_registry.py --geocode dengue
```

```bash
# Feature work
git checkout develop && git pull
git checkout -b feature/x
# ... commits ...
git push origin feature/x
# Open PR → develop. After merge:

# Deploy to staging
ssh user1@dbsvr 'cd /var/www/html/hmap_staging && \
    git pull origin develop && \
    cd laravel && composer install --no-dev && npm ci && npm run build && \
    php artisan optimize:clear && \
    sudo systemctl restart hmap-ml-staging'

# Test on hrmo.paranaque.gov.ph:8080/hmap/

# Deploy to production (after PR develop → main is merged)
ssh user1@dbsvr 'cd /var/www/html/hmap && \

    cd laravel && composer install --no-dev --optimize-autoloader && \
    npm ci && npm run build && \
    php artisan optimize && \
    sudo systemctl restart hmap-ml'
```

    cd /var/www/html/hmap_staging && \
    DB_NAME=hmap_db_demo ml/.venv/bin/python ml/detect_clusters.py'

## Anonymization spec (what's safe to show)

The staging DB only has the following PII transformations from real data
(per `ml/anonymize_for_demo.py`):

| Field | Real | Demo |
|---|---|---|
| `case_addresses.raw_street_purok` | "12 Quirino Ave, BF Homes" | NULL |
| `case_addresses.geocode_query` | full address text | NULL |
| `case_addresses.geocode_formatted` | Nominatim formatted hit | NULL |
| `case_addresses.case_lat / case_lng` | exact geocoded point | jittered ±50m (uniform) |
| `cases.date_onset` | exact | shifted ±3 days |
| `cases.date_admitted / date_reported` | exact | shifted by same delta as onset |
| `cases.age` | exact | bucketed to age-group midpoint (2,7,12,17,40,70) |
| `cases.morbidity_year/week/month` | exact | recomputed from shifted onset |

**Re-identification risk is low** because:
- The schema never stored names, phone numbers, or HMO/PhilHealth IDs.
- The 50m jitter is well below the 200m cluster eps (cluster patterns survive).
- The 3-day shift preserves weekly epi curves and 5-year baseline analytics.
- The age bucket destroys exact birth-date inference.

The jitter is deterministic (seed=20260523) so re-running anonymization
produces the same demo dataset; change `--seed` to rotate it.

## Rollback

If a deploy breaks something:
```bash
ssh user1@dbsvr 'cd /var/www/html/hmap && git log --oneline -5'
# Pick the previous commit:
ssh user1@dbsvr 'cd /var/www/html/hmap && git reset --hard <prev-sha> && \
    cd laravel && npm run build && \
    sudo systemctl restart hmap-ml'
```
